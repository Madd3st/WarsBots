# WarsBots: инструкции для агентов

## С чего начать

1. Прочитать [актуальный статус](Docs/STATUS.md) и задачу пользователя.
2. Проверить `git status --short` и текущую ветку. Не перезаписывать чужие изменения.
3. Читать только нужные функции: сначала `rg`, затем небольшой фрагмент файла.
   Не сканировать весь SDK и не перечитывать всю документацию без необходимости.

Репозиторий: https://github.com/Madd3st/WarsBots.
Рабочая ветка на момент передачи: `codex/warsbots-abilities`.
Текущая незавершённая фаза: [передача прогресса abilities](Docs/ABILITIES_PROGRESS.md).
Продолжать существующий проект и историю Git; не создавать второй проект.

## Карта кода

| Область | Где искать |
| --- | --- |
| Вход/выход игрового модуля | `Code/Mod/Game.cpp`, `Game.h`; `Bots/BotManager.*` |
| Создание, владение EntityId, удаление, уровень, respawn, консоль | `Code/Mod/Bots/BotSpawner.*` |
| Состояния, решения 10 Гц, память цели, патруль, 5-секундный respawn | `Code/Mod/Bots/BotBrain.*` |
| Обнаружение, LOS, последнее видимое положение, очереди | `Code/Mod/Bots/BotCombat.*` |
| Запросы движения, препятствия и застревание | `Code/Mod/Bots/BotMovement.*` |
| Поиск/подбор оружия, боезапас, SCAR fallback | `Code/Mod/Bots/BotWeapons.*` |
| Поворот/анимация и передача motion клиенту | `Code/Mod/Player.cpp`: `SetWarsBotMotion`, `UpdateWarsBotMotion`, `NetSerialize`, `PrePhysicsUpdate` |
| Урон, убийства и узкая проверка серверных снарядов | `Code/Mod/GameRules.cpp`, `GameRulesClientServer.cpp`, `ShotValidator.cpp` |
| Интерфейсы движка, а не реализация закрытых DLL | `Code/CryEngine/` |
| Сборка | `Scripts/Build-WarsBots.ps1`, `CMakeLists.txt`, `CMakePresets.json` |

Вся папка `Code/Mod/` содержит также исходную игровую логику SDK.
Собственная логика бота сосредоточена в `Code/Mod/Bots/`; изменения общих классов
ограничивать собственным актёром и `WARSBOTS_EXPERIMENTAL_SPAWNER`.

## Инварианты

- Экспериментальная сборка по умолчанию OFF; runtime gate по умолчанию 0.
  AI запускается только явной `wb_bot_start` на локальном Instant Action:
  `sv_bind=127.0.0.1`, `sv_lanonly=1`, `wb_probe_local_test=1`.
- Единственный `WarsBot_01` — Player с channelId=0 и IsPlayer=false.
  Не создавать фиктивный INetChannel и не обращаться к отсутствующему каналу.
- Сохранять проверку владения сущностью, обработку ENTITY_EVENT_DONE и конца уровня.
  RevivePlayer возрождает того же актёра; удаление/stop отменяют автоматический respawn.
- Урон и стрельба идут штатным оружием через GameRules; не заменять их прямым
  изменением HP или искусственным убийством. Не расширять исключение ShotValidator.
- LOS должен признавать физические части той же IEntity целью: указатель физики
  может отличаться. Непрозрачная стена остаётся препятствием; muzzle LOS проверяется отдельно.
- Условные поля сетевого аспекта оформлять `BeginOptionalGroup`/`EndGroup`.
  Сервер и клиенты должны иметь совместимую версию экспериментальной DLL.
- Не менять стандартных игроков, Power Struggle, транспорт или масштаб проекта
  без соответствующей задачи пользователя. Полноценного pathfinding пока нет.

## Работа и проверка

- Не запускать параллельных AI-агентов без явного запроса пользователя.
- Не устанавливать инструменты без необходимости; не подменять MSVC несовместимым ABI.
- Сборка на Windows: `.\Scripts\Build-WarsBots.ps1 -ExperimentalSpawner`.
  Выход: `build/release-bin64-probe/Mods/WarsBots/Bin64/WarsBots.dll`.
  Обычная сборка: тот же скрипт без флага, каталог `build/release-bin64/`.
- Для изменений только Markdown достаточно проверить diff и ссылки; DLL не пересобирать.
  Успешные проверки повторять только при новых изменениях или нерешённой проблеме.
- DLL устанавливать только при свободном файле. Не прерывать пользовательскую игру
  без согласования. Не использовать `+quit` или короткий таймер для игровых тестов:
  дождаться готовности сервера, подключения клиента и результата проверки.
- Различать компиляцию, серверные логи и визуальный тест. Не объявлять анимацию,
  LOS во всех условиях или статистику матча подтверждёнными без соответствующих тестов.
- Сначала обновлять `Docs/STATUS.md`, если изменился статус проекта; остальные документы
  менять по необходимости, без большого переписывания. Краткий итог: изменения,
  выполненные проверки, ограничения. Не добавлять игровые бинарники/ресурсы в Git.
- Сохранять лицензию Crytek из `LICENSE.txt`; не объявлять SDK MIT/GPL.
