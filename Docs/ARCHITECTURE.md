# Архитектура WarsBots

## Реализовано

`GameDll.cpp::CreateGame` выполняет `ModuleInitISystem` и создаёт `CGame`.
В конце успешного `CGame::Init` вызывается `m_botManager.Initialize()`.
Менеджер хранится по значению в `CGame`, без singleton и выделяемых ресурсов.
Повторный Initialize не дублирует лог. `CGame::Shutdown` вызывает деструктор
`CGame`, который завершает менеджер перед освобождением игровых систем.
Shutdown менеджера идемпотентен. Интерфейсы и ABI CryEngine не меняются.

Инициализация относится к жизни CGame, а не матча. Она происходит и на клиенте:
серверный контекст на этапе Init может ещё не существовать. Для будущей симуляции
проверять `gEnv->bServer` при работе с матчем, а не запоминать его навсегда при Init.
В каркасе нет Update, SpawnBot, консольных команд и Lua-подмен с фиктивным успехом.

## Планируемые компоненты — пока не реализованы

| Компонент | Ответственность |
| --- | --- |
| BotManager | Реестр по EntityId, создание/удаление, лимиты, очистка при смене карты. Отдельно от настоящих сетевых каналов. |
| BotController | Один актёр: перевод намерений в движение, оружие и нанокостюм; безопасное разрешение EntityId вместо долговечного сырого указателя. |
| BotNavigation | Маршрут и ближайшая цель; сначала waypoint-граф проверочной карты. CryAI только после проверки в MP. |
| BotCombat | Видимость, допустимость цели, оружие, прицеливание, стрельба через штатную серверную логику. |
| BotBrain | Состояния Dead / Spawning / Idle / Moving / Engaging; выдаёт намерения, не вызывает сетевые API. |
| BotGameMode | Контракт вступления, команды, условий respawn, смерти и очков. Это проектный контракт, не существующий API движка. |
| IABotLogic | IA: свободные противники, штатный scoring и respawn. |
| PSBotLogic | PS: команда, захват, разрешённые покупки за Prestige Points через исследованные серверные правила. |

Поток: BotGameMode → BotBrain → Navigation/Combat → BotController → актёр →
штатные аспекты/RMI → клиенты. BotManager управляет жизненным циклом компонентов.

## Решения

1. Сначала чистая сборка SDK и smoke test каркаса. Функциональность ботов добавлять
   после подтверждённой DLL и журнала загрузки.
2. Сервер авторитетен. Не создавать фиктивных INetChannel и не вызывать OnClientConnect
   для несуществующего соединения: в synched storage найдена разыменовка null.
3. Направление исследования — актёр без соединения и отдельная регистрация участника
   в GameRules. Пригодность channelId=0 для полноценного игрока **не доказана**:
   невиртуальный `IsPlayer()` зависит от channelId.
4. Не расширять виртуальные интерфейсы IActor/IGameObject и не менять их layout:
   движок бинарный. Расширения реализовать на уровне игрового мода.
5. Исследовать отдельный IPlayerInput и точку выбора в CPlayer. CNetPlayerInput
   ожидает сетевые обновления и имеет timeout; однократного SetState недостаточно.
   Серверная authority input-аспекта требует отдельной проверки.
6. Скрипты IA/PS отсутствуют в исследованной базе: до их изучения из установленной
   1.5 не придумывать функции покупки/захвата.
7. Не переносить глобальное переключение `gEnv->bMultiplayer` из Co-op.

Будущий match lifecycle должен обрабатывать удаление актёров, рестарт, смену карты
и правил, позднее подключение клиентов. Сейчас менеджер не хранит сущностей.
